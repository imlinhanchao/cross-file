### Snapdrop (predecessor) — status as of 2026-11-24
Snapdrop is now split in two, and neither half is the 2019-2022 project:
- **snapdrop.me** serves the classic UI (device avatars on the same network, "You can be discovered by everyone on this network") and asks for microphone permission with the note "Allowing microphone access helps Chrome connect to nearby devices" (a WebRTC discovery workaround). Its GitHub repo (RobinLinus/snapdrop) shows a Rust backend, a commit "Replace snapdrop.net with snapdrop.me" (2026-09-14) and a last commit on 2026-09-15; **no GitHub releases exist**.
- **snapdrop.net** now runs an ad-supported site with an InMobi/Google consent stack and Google Analytics, offering "Direct transfer" (WebRTC, "nothing is stored") **plus** a "Share link" mode backed by **LimeWire** (10 GB without an account, 3 days, paid plans raise it). Its own copy says direct transfer "was replaced by an upload page" and is now "back, rebuilt from scratch", adding 6-digit code / QR linking across networks.
Sources: snapdrop.me, snapdrop.net, GitHub RobinLinus/snapdrop (README + commits API).

## (a) Which need is still genuinely underserved

No tool read here covers browser-only receiver + zero server storage + 500 MB + NAT traversal. PairDrop and FilePizza are browser-only and store nothing, but PairDrop falls back to its own TURN for NAT'd peers and its FAQ concedes "you have to trust the PairDrop server" (zero-trust is issue #180); FilePizza requires "that the uploader leave their browser window open until the transfer is complete" and bounds size by "as big as your browser can handle". Wormhole covers cross-network with no install only by storing files (<=5 GB, 24 h) - the opposite of zero storage - and its >5 GB mode again needs both parties online. The fast zero-storage tools need a receiver install: Blip answers "Can I share files with web links? No". Native options are walled: Quick Share has no iOS client, Nearby Sharing is Windows-to-Windows only, AirDrop is Apple-only. Resume is thinner still: documented for Blip, croc and Filemail's apps, for no browser tool.

## (b) Documented pain points / failure modes

**TURN relay cost and speed.** PairDrop: when paired devices sit behind different NATs, "traffic needs to be routed through the TURN server... transfer speed decreases", and the suggested workaround is opening a phone hotspot. Its tech doc adds that a rogue TURN server "could only see that there is a connection". Syncthing documents the same trade-off ("much lower than a direct connection"), and croc warns public DERP is "best effort and may apply fairness limits".

**iOS.** PairDrop records that iOS did not allow images shared from a website to be saved to the gallery (a WebKit bug, since fixed; an iOS Shortcut was the workaround), and snapdrop.me still asks for microphone access because Chrome needs it to discover nearby peers. Wormhole has no mobile app yet ("We're working on mobile apps!").

**LAN discovery.** LocalSend 1.18.2 fixes "restore compatibility with 1.17.0 and earlier versions on missing multicast networks" and auto-restarts its "HTTP / multicast server when it dies or when the app resumes". Microsoft documents the same class: device not visible, network profile must be Private, Bluetooth LE required.

**Size caps.** Wormhole 10 GB headline but 5 GB stored; WeTransfer free 3 GB/month; Smash free 2 GB with over-2 GB transfers queued ("uploaded to our servers and sent after a waiting period"); Microsoft documents "Nearby sharing failing with large files" and advises zipping.

**Expiry.** Wormhole deletes server copies after 24 h; Send Anywhere links last 48 h; WeTransfer free expiry "up to 3 days"; croc store defaults to one day and one download, whichever comes first; snapdrop.net's LimeWire links last 3 days.

**Mobile download UX.** PairDrop zips multiple files and warns before the tab closes mid-transfer; FilePizza needs the sender's tab alive, so on mobile the screen must stay awake.

## (c) Strongest UX elements worth learning from

- **QR handoff**: PairDrop pairs via "6-digit code or a QR-Code"; croc's `--qr` opens getcroc.com in receive-only mode; CrocApp adds QR codes and the iOS share sheet.
- **Short codes**: PairDrop's 5-letter room code and 6-digit pairing code; croc's EFF-style "code-phrase" (custom codes >=6 characters), copied to the clipboard by default; Magic Wormhole's "short and human-pronounceable" words from a phonetically distinct, single-use list with tab-completion; Send Anywhere's "one-time 6-digit key".
- **Room links**: PairDrop temporary public rooms; Wormhole's `https://wormhole.app/<room-id>#<key>` keeps the key in the URL fragment "never sent to the server"; croc store does the same with `#v1.decryption-key`.
- **Resume**: Blip ("resumes after network interruption, drives being unplugged, full disks"); croc lists resuming interrupted transfers; Filemail ships resume in its desktop apps.
- **Progress and integrity**: Wormhole verifies every WebTorrent piece and discards failures; LocalSend added checksum support "enabled by default" in 1.18.0; PairDrop shows "an overall progress indicator".
- **Clipboard/text**: croc `--text`, PairDrop's paste-then-pick-recipient flow, KDE Connect's shared clipboard, LocalSend's `--text/-t` CLI flag.
